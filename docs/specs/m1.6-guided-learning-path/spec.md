- Spec ID：`m1.6-guided-learning-path`
- 状态：Verified

- 验证日期：2026-10-29
- 里程碑：M1 上下文管理与可观测性
- 关联 ADR：ADR-004 Read-only Agent Anatomy（延续只读投影与无 Web 执行入口）
- 关联 Baseline：[M1_2_COMPACTION_BASELINE.md](../../M1_2_COMPACTION_BASELINE.md)

## 1. 背景与问题

M1.5 把 Trace、任务契约、fixture、check 语义和可观察因果链都放进了页面，但默认“任务故事”仍是一份面向已经理解 Agent Loop 的读者的证据报告。真实使用反馈是：初学者打开页面后不知道从哪里开始，无法快速回答以下问题：

1. Agent 除了大模型之外还有哪些组件，它们各自做什么；
2. 这些组件在什么时机、什么位置参与；
3. 页面中的测试是在测模型、测工具，还是测实验本身；
4. `PASS / FAIL / SKIP / UNKNOWN` 到底在评价什么；
5. 当前这次运行发生了什么，为什么最终判失败。

现有页面不是信息不足，而是**学习顺序缺失**：默认页面先进入具体失败任务，再连续展示实验契约、因果链、Loop、工具、原始轮次、check 卡片、最终响应和 takeaways。证据密度超过了初学者一次能建立的模型。

另外，Dashboard 的 observation 摘要把 `has_more` 误写成“是否到达文件末尾”。在真实 Trace 中，`has_more=false` 可以表示本次请求范围已读完，而 `file_has_more=true` 仍表示文件后面还有内容。这个错误会直接影响“Agent 为什么停止”的理解，也会把“只读了 44/85 行后停止”误写成“已到文件末尾”。

## 2. 目标

1. 将默认入口改为五步学习路径，每次只回答一个问题，而不是继续拉长报告；
2. 用“任务 → 组件 → 循环 → 判定 → 复盘”的顺序建立 Agent 心智模型；
3. 对每个组件明确展示作用、参与时机、代码/架构位置和本次运行状态；
4. 将测试分成最终验收、过程约束、能力证据、实验完整性四层，并解释每层在评价什么；
5. 把当前运行压缩成四张故事卡：任务、过程、断点、裁判；
6. 明确展示“文件仍有后续但 Agent 停止”的可观察证据，不推断内部动机；
7. 修正 `has_more` 与 `file_has_more` 的展示语义，并增加回归测试；
8. 保留 Story、Replay、Anatomy、Compare 作为深入证据视图，且不改变已导入数据。

## 3. 用户故事或实验场景

- 作为第一次接触 Agent 的学习者，我打开 Dashboard 后能在 5 分钟内知道先看什么、后看什么。
- 作为学习者，我能在同一页看到模型、上下文、Loop、工具、约束和评测分别负责什么，以及本次是否真正参与。
- 作为学习者，我能用四张卡复述本次实验：任务要求什么、Trace 记录了什么、Loop 在哪里停止、Eval 为什么判失败。
- 作为学习者，我能理解测试不是模型思维的一部分，而是运行结束后的外部裁判。
- 作为学习者，我能区分“答案没交付”“工具真的执行”“实验条件没有触发”和“证据不足”。
- 作为维护者，我能从每个学习步骤一键进入原始证据，但不会在首屏被全部原始证据淹没。
- 给定一个第二轮读取后 `has_more=false`、`file_has_more=true`、`next_start_line=45` 的 Trace，页面不得显示“已到文件末尾”，而应显示文件仍有后续内容。

## 4. 范围

- 新增默认的 `开始学习` 视图和五步路径导航；
- 新增运行级“任务 / 过程 / 断点 / 裁判”四张故事卡、分层判定摘要和“未消费的续读证据”展示；
- 新增组件地图，覆盖任务 Prompt、Context、Model、Agent Loop、Tool Registry、Approval、Compaction、Trace、Eval；
- 新增 Loop 学习图，用当前真实任务展示模型判断、工具调用、Observation 回写和停止分支；
- 新增测试学习区，按四类评价标准解释当前 checks，并将逐条证据默认折叠；
- 修正 `Story.observationSummary` 的 `has_more / file_has_more / next_start_line` 文案；
- 新增纯函数、静态结构、浏览器布局和可达性验证；
- 同步 SDD、README、Roadmap 和规格索引。

## 5. 非目标

- 不改变 Agent Loop、Prompt、模型、工具 Schema、审批或压缩策略；
- 不新增 Live Eval，不把单次运行升级为统计结论；
- 不展示模型内部思维链，不把字段接力写成动机因果；
- 不新增后端、框架、CDN、npm 依赖或在线调参；
- 不执行工具、不提供写入入口；
- 不删除现有 Story、Replay、Anatomy 和 Compare 证据视图；
- 不重构导出数据 schema，除非为兼容旧数据所必需。

## 9. 指标

- 首屏结构：由一个主结论、四张“任务 / 过程 / 断点 / 裁判”故事卡和一个“下一步”动作组成；原始事件默认折叠；
- 学习路径长度：固定 5 步，每步只承担一个核心问题；
- 术语覆盖：组件地图包含 9 个组件/证据节点，测试区包含 4 类评价标准；
- 解释覆盖：默认 Trace 的四张故事卡、读取覆盖和 continuation gap 均可回到真实事件；
- 技术回归：既有 74 项测试基线不回退；当前共 76 项测试，覆盖分页摘要、continuation gap 和默认学习结构；
- 浏览器质量：桌面/移动端横向溢出 0、runtime error 0、console error 0、external request 0。

## 10. 安全与边界

- 本变更是本地只读页面重构，不运行模型、工具或 shell；
- 页面不新增外链资源、网络请求或提交入口；
- `dashboard/data.json` 仍是 ignored 的 `local-unredacted` 数据，禁止提交；
- 组件位置来源于 `catalog.modules` 与工具 registry，不根据模型回答猜测；
- continuation gap 只说明 Trace 中的结构和字段，不推断“模型为什么没有继续”；
- 单次 A/B 仍只能定位差异，不能证明策略因果。

## 11. 风险与未决问题

- 风险：学习路径过度简化，掩盖证据边界。缓解：每一步都保留“查看原始证据”入口，并显示单次实验边界。
- 风险：组件地图把“组件”与“观测旁路”混在一起。缓解：分为“循环内组件”“按条件出现”“旁路证据”三条车道。
- 风险：用固定叙述模板解释所有任务，造成错误归因。缓解：所有文本由当前 record、checks、events 和 contract 生成；无证据时显示未记录。
- 风险：学习视图与 Story 视图出现两套事实。缓解：两者复用同一 `summarizeExperiment`、`groupRounds` 和 `toolPath` 结果。
- 待决：未来是否增加“交互式一步步高亮 Loop”；本轮仅提供步骤切换和真实事件跳转。

## 12. 完成条件

- 所有 AC 有确定性、DOM 或浏览器证据；
- `has_more / file_has_more` 回归用例通过；
- 不新增 Live Eval，并记录理由；
- 现有证据视图仍可访问；
- README、Roadmap、规格索引和实施记录同步；
- 不修改或提交 `dashboard/data.json`。
