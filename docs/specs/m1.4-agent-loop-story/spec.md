## 1. 背景与问题

M1.3 已让模块、工具、Trace 和 A/B 指标来自真实代码与报告，解决了“证据是否存在”的问题。但对第一次接触项目的人来说，首页仍然先展示工程结构，存在四个理解障碍：

- 用户首先想知道“这次 Agent 做了什么”，而不是“系统由哪些模块组成”；
- 24 至 37 条事件被平铺后，模型轮次、工具调用和回到模型的反馈关系不明显；
- 七张工具卡片权重相同，看不出本次真正插入了哪些“零件”；
- A/B 页面展示结果差异，却没有指出第一个可复核的判定或路径分叉；
- observation 和完整 JSON 占据大量视觉空间，人话解释反而不突出。

本轮不新增 Agent 能力，只把已有真实数据重新组织为更接近学习心智模型的证据叙事。

## 2. 目标

把本地只读 Dashboard 从“工程观测台”提升为“可讲清一次 Agent 运行的学习界面”：

1. 默认先展示一次真实任务的故事，而不是架构目录；
2. 按模型轮次组织事件，用确定性文案说明每轮看到什么、做了什么、得到什么；
3. 用真实事件驱动环形 Loop 和工具条件分支，表达 `Model → Tool → Observation → Model` 的回环；
4. 把本次使用的工具突出为“已插入零件”，其余工具保留在可展开工具箱中；
5. 将 A/B 的第一处任务或 check 分叉提到页面前部，并可直接进入两条真实 Trace；
6. 将原始 JSON 降级为默认折叠的证据，不删除真实载荷。

## 3. 用户故事或实验场景

- 作为初学者，我打开页面后先看到任务结果、真实工具路径、每一步的人话说明和最后响应，再决定是否深入源码。
- 作为学习者，我希望在 Loop 中看到本轮模型是否调用了工具，以及 observation 如何回到下一轮，而不是只看到一排线性编号。
- 作为学习者，我希望“本轮插入了 read_file”以及“这次没有使用 grep”都来自真实 Trace。
- 作为比较实验者，我希望看到 A/B 第一个结果不同的任务、第一处 checks 分叉和进入两侧 Trace 的入口，同时明确这只是单次快照。
- 给定任一真实事件，我可以在详情中先读摘要，再按需展开完整 observation 与 JSON。
- 给定没有数据文件的 checkout，页面仍显示真实导出命令而不是演示故事。

## 4. 范围

- 重构 Dashboard 的默认视图和导航文案；
- 新增基于事件数据的模型轮次分组和确定性人话摘要；
- 新增事件驱动的回环与分支图；
- 调整工具卡片层级、模块卡片与已调用工具的高亮；
- 新增 A/B 首次分叉定位；
- 调整事件详情的信息层级与原始证据折叠；
- 增加纯函数测试、静态检查、真实数据导出验证和浏览器验收；
- 同步 README、Roadmap、规格索引和实施记录。

## 5. 非目标

- 不生成或补录用户原始 Prompt；
- 不根据最终答案倒推模型当时没有记录的理由；
- 不改变 Agent Loop、模型请求、工具 Schema、审批、压缩策略或 checks；
- 不新增 Live Eval，不把当前单次 A/B 快照升级为统计结论；
- 不在浏览器启动 Agent、执行工具或开放在线调参；
- 不引入前端框架、构建链、CDN、后端或外部字体；
- 不提供自由拖拽编排；本轮的“乐高”仅表示可识别、可追溯、可点击的模块和工具插槽；
- 不把 observation 截断称为脱敏。

## 9. 指标

本轮是展示层变更，不新增 Agent 成败指标。验收指标为：

- 默认首屏理解路径：结果 → 路径 → 轮次 → 零件；
- 轮次分组覆盖率：每个有 `step` 的事件必须进入对应轮次，无 `step` 事件进入 run-level；
- 工具路径准确率：已使用工具集合必须与 `tool_call` 事件集合完全一致；
- A/B 分叉可追溯率：显示的任务和 check 必须能在两侧记录中找到；
- 浏览器：0 runtime error、0 external request、390px 0 horizontal overflow；
- 回归：既有确定性测试全部通过，新增 story 测试通过。

## 10. 安全与边界

- 页面只读取本地导出的 JSON，不执行模型或工具；
- 不读取或请求 `dashboard/data.json` 之外的本地文件；
- 展示内容仍可能包含真实 observation，继续标记为 `local-unredacted`；
- 故事中的工具参数和 observation 只来自 Trace；checks 是任务判定证据，不等于模型内部推理；
- 本轮不改变审批和路径 Guardrail，也不宣称沙箱隔离。

## 11. 风险与未决问题

- 风险：人话摘要可能被误读为模型自述。缓解：统一使用“记录显示/本轮调用/根据 checks”措辞，并保留原始证据。
- 风险：不同报告字段不完整导致轮次断裂。缓解：缺失字段显示未记录，无 `step` 事件进入独立 run-level 区。
- 风险：视觉回环过度简化真实异常路径。缓解：异常、压缩、审批和完成分支都读取真实事件，不画未发生的条件。
- 待决：在线调参和受控运行需要另立规格，处理工作区、审批、密钥、超时、取消与清理，不能借本轮 UI 顺带实现。
