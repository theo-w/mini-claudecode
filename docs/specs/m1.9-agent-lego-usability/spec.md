# Agent Lego Usability Repair Specification

- Spec ID：`m1.9-agent-lego-usability`
- 状态：Verified
- 日期：2026-10-29
- 验证日期：2026-10-29
- 里程碑：M1.9
- 关联 ADR：无
- 关联 Baseline：无（仅修正教学展示与交互，不改变 Agent runtime）

## 1. 背景与问题

M1.8 已提供 8 个零件的自由装配、确定性重放、A/B 和实验历史，但浏览器验收暴露出三个影响理解的产品问题：

- 1440 × 1000 下，Hero 约 387px、任务卡约 188px，装配区顶部约 799px，首次用户看不到“开始实验”的动作；
- 390 × 844 下，装配区顶部约 1198px，导航内容宽约 535px，可视宽度约 354px，存在横向溢出；
- `read_file + write_file + run_python + loop + eval` 的结果为任务 `PASS`、边界 `UNKNOWN`、轨迹 `OFF`、证据 `EVAL_ONLY`，但解释写成“动作链、执行边界、系统轨迹和任务验收都已接通”，把“任务被验收”错误等同于“运行完整可信”。

同时，A/B 直接比较最近两次运行，没有检查单变量条件；多块零件同时变化时，用户可能把结果错误归因给某一个组件。

## 2. 目标

- 让首次进入者在首屏看到一个明确主行动：先跑一次空装配基线。
- 运行后自动把装配与结果带入视野，并给出“撞墙 → 选一个补丁 → 再运行”的下一步。
- 将“任务验收 / 执行边界 / 可审计性”呈现为三个独立结论，任何文案都不得把未装配能力说成已接通。
- 让 A/B 明确区分单变量对照、重复运行和多变量变化。
- 让零件卡说明“没有它会怎样”，优先使用后果语言而不是架构名词。
- 保持纯前端确定性教学模拟，不新增真实执行通道。

## 3. 用户故事或实验场景

- 作为 Agent 初学者，我进入页面后不需要先读完 Hero 和任务卡，就能点击“先跑一次基线”。
- 作为学习者，我看到任务通过时会同时看到“执行边界 UNKNOWN / 可审计性 NONE”，不会误以为整个 Agent 可信。
- 作为实验者，我完成一次运行后，系统只推荐一个最小补丁；点击后只增加这一块并再次运行。
- 作为复盘者，如果我同时改变多块零件，A/B 会提示“多变量变化，不能归因给单一组件”。
- 作为手机用户，我能看到首屏主行动，页面没有横向溢出，并可通过点按完成全部操作。

## 4. 范围

- 调整 `06 乐高实验` 的 Hero、首屏主行动、任务摘要和移动端布局。
- 新增“先跑一次基线”与“只加一块并再跑”的引导交互。
- 为 8 个零件补充 `missing` 后果说明。
- 重构结果区：三个独立结论卡，治理细节作为第二层展开。
- 修正 `simulateRun.narrative` 的能力声明语义。
- 扩展 `compareRuns`：返回变化组件集合、单变量标志和多变量提示。
- 乐高视图隐藏与固定脚本化模型冲突的全局运行选择器。
- 更新 M1.9 Spec、Plan、Tasks、Implement、README、ROADMAP 和规格索引。

## 5. 非目标

- 不调用模型 API，不执行工具，不上传数据。
- 不改变 Harness runtime、工具协议、审批策略或真实 Eval。
- 不增加 Skill、Memory、RAG、MCP、Subagent 或多 Agent。
- 不把教学模拟耗时当作真实性能基准。
- 不持久化实验历史。

## 9. 指标

- 首屏主行动可见性：1440 × 1000 与 390 × 844 均为 `visible`。
- 装配区起始位置：目标桌面 `< 650px`，移动端 `< 900px`。
- 横向溢出：桌面和移动端均为 0。
- 语义穷举：256/256 个装配无虚假能力声明。
- A/B 归因：多变量变化必须出现明确警告。
- 引导候选：每次 `1..3` 个；本轮不评估真实学习效果。

上述布局指标是产品可用性阈值，不是 Agent 性能指标。

## 10. 安全与边界

- 本变更只修改静态 HTML/CSS/JavaScript 与文档。
- 不从 `dashboard/data.json` 读取或提交用户数据。
- 不增加真实工具调用、网络请求、文件写入或子进程执行。
- “执行边界 PASS”仍只表示教学脚本经过规则检查，不代表 OS 级 Sandbox。

## 11. 风险与未决问题

- 风险：为了缩短首屏而删掉必要解释。缓解：把解释移到实验区结果和“为什么”层，不删除安全边界。
- 风险：推荐补丁被误读为唯一正确路线。缓解：文案明确它是“本次固定任务的最小下一步”，候选最多 3 个，并保留自由装配。
- 风险：三结论卡增加结果区密度。缓解：结论优先、治理细节保留但下沉。
- 待决：未来若支持真实运行，需要独立设计 Sandbox、审批、资源限制和清理。

## 12. 完成条件

- 所有 AC 有测试、DOM 契约或浏览器 QA 证据；
- 256 组合语义检查通过；
- 桌面与窄屏无横向溢出，主行动可见；
- 文档和规格索引同步；
- 不新增 Agent runtime 或真实执行能力。
