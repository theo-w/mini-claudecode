## 1. 方案摘要

保留 M1.8 的确定性模拟内核，只修正“第一次怎么开始、结果怎么读、下一步改什么”。首屏增加空装配基线按钮；结果层把任务、安全、审计拆成三张独立结论卡；A/B 用集合差判断是否单变量；引导函数只返回 1–3 个可单步装入的补丁候选。布局通过压缩 Hero、任务摘要和移动端导航，把装配区提前到首屏附近。

## 6. 测试策略

### 确定性测试

- 正常路径：空装配得到 `BLOCKED`，推荐 `read_file`；加读取后推荐 `loop`。
- 语义路径：穷举 256 个装配，检查三类结论与 narrative 不越过实际能力。
- 比较路径：0 个变化为重复运行，1 个变化为受控对照，多个变化必须警告。
- 引导路径：候选数量为 0–3，且每个候选只相对当前装配增加一个组件。
- 页面契约：存在基线按钮、下一实验容器、三结论容器，且乐高页可隐藏 run picker。

### Live Eval

不适用。本次不改变 Agent runtime、Prompt、工具、Eval 或模型调用。

## 7. 安全与失败处理

- 高风险工具：无新增。
- 审批策略：不修改。
- 超时/取消：教学定时器沿用 M1.8；离开或切换视图不引入真实进程。
- 回滚方式：恢复 M1.8 的 HTML/CSS/JS 和 lego 纯函数即可。
- 已知限制：推荐只针对固定任务的确定性断点，不外推到真实任务。

## 8. ADR 需求

不需要。变更不改变系统架构、安全边界或协议，只修正教学界面与解释。
