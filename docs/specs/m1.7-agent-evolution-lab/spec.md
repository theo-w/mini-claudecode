## 1. 背景与问题

当前 Dashboard 已能解释一次真实 Agent 运行的结论、组件、Loop、测试与证据边界，但其入口仍建立在“完整 Agent 已经存在”这一前提上。对不熟悉 Agent 的学习者，需要同时理解 Tool、Observation、Loop、Trace、Eval 等概念，阅读负担较高，且难以回答“这个组件为什么必须出现”。

早期最小 function-calling loop 代码包含 `tool_use → 工具执行 → tool_result → 下一次模型请求` 的核心骨架，但也同时包含多工具、Shell 执行、字符串黑名单和硬编码模型等复杂内容。直接把它作为第一章会混淆协议、安全与教学重点。

因此需要一个从最简单版本开始、由具体失败驱动能力增长的课程入口。课程必须让学习者在增加每个组件之前先看到旧版本的局限，并在增加后看到可观察变化。

## 2. 目标

- 提供独立的 `从零建造` 学习视图，并作为 Dashboard 默认入口。
- 用 7 个单概念章节构建最小 Agent：只有模型、单工具、Tool Loop、Registry、安全边界、Trace、Eval。
- 每章固定回答：为什么需要、只加什么、运行后看到什么、边界是什么、如何检查理解。
- 将 Tool 与 Skill 明确区分；Skill 只作为后续路线，不在基础章节中提前实现。
- 保留现有真实 Trace 解剖、五步学习、Loop 回放、乐高拆解和 A/B 对比。
- 课程在 `dashboard/data.json` 不存在时仍可阅读；真实数据视图显示明确的数据缺失提示。

## 3. 用户故事或实验场景

- 作为不了解 Agent 的学习者，我希望先只理解“模型不能行动”，再看到工具如何加入，从而不被完整 Trace 淹没。
- 作为已经能运行示例的学习者，我希望每章只增加一个机制，并能看到缺失该机制时的可观察后果。
- 作为产品学习者，我希望课程明确说明 Skill 为什么在 Tool、Trace、Eval 之后才出现，而不是把术语堆在一起。
- 给定课程已加载，当我切换章节、回答检查题或调整浏览器宽度时，当前章节、反馈和布局仍然清晰可读。
- 给定 `dashboard/data.json` 不存在，当我打开页面时，仍能使用从零建造课程；进入真实 Trace 视图时才看到导出提示。

## 4. 范围

- 新增静态课程数据模块、默认课程视图、章节导航、检查题和后续路线预览。
- 课程包含 7 章：
  1. 只有模型
  2. 加第一个工具
  3. 形成 Tool Loop
  4. 多工具与 Registry
  5. 安全边界与审批
  6. Trace
  7. Eval
- 课程输出为确定性教学快照，并明确标注“不执行工具”。
- 更新导航、版本、README、ROADMAP、规格索引和实现记录。

## 5. 非目标

- 不新增网页内代码执行、Shell、模型调用或 Live Eval。
- 不改变现有 Agent Loop、工具 Schema、消息协议、审批和压缩行为。
- 不实现 Skill、MCP、RAG、Memory、Subagent 或多 Agent。
- 不把教学快照伪装成真实模型运行。
- 不替换现有真实 Trace 证据视图；它作为完成基础课程后的进阶层。

## 10. 安全与边界

- 课程是静态只读内容，不接收文件路径、命令或模型凭据。
- 页面不执行代码，不调用模型，不读取 Trace 作为课程运行的证据。
- 安全章节只展示防御原则和抽象伪代码，不提供可复制的绕过命令。
- 审批是策略闸门；真正隔离需要容器、虚拟机或操作系统级权限控制。
- 现有 `dashboard/data.json` 的 local-unredacted 警告和只读边界保持不变。

## 11. 风险与未决问题

- 风险：7 章继续变成长篇文档。缓解：每章只解决一个问题，代码与输出短小，详情默认折叠。
- 风险：教学代码与真实 Harness 协议漂移。缓解：第 3 章之后链接到现有真实 Trace 视图；后续可增加代码映射测试。
- 风险：用户把确定性快照误认为真实运行。缓解：每章和页脚持续标注。
- 待决：真正可执行的 Try it 需要在独立沙箱中实现，不属于本次只读 MVP。
