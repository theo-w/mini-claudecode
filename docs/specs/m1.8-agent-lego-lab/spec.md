## 1. 背景与问题

M1.3–M1.7 已经能解释一次真实 Agent 运行，但主要交互仍是“阅读已经装配好的系统”：可以看模块、工具、Loop、Trace 和 Eval，却不能在同一个任务里亲手拆装，再立即比较“有它 / 没它”的结果。

这会让学习停留在识别名词：

- 知道 Tool 让模型能行动，但没看到“只有工具、没有 Loop”时为什么仍会停住；
- 知道 Eval 重要，但没看到同样完成 `3/3` 动作时，`UNVERIFIED` 与 `PASS` 的差别；
- 知道 Guardrail、Trace 是治理层，却容易误以为它们会提高模型解题能力；
- 能看到 A/B 真实报告，但实验成本高，不适合先做低成本、可重复的机制推演。

因此需要一个独立的交互式教学实验台：固定任务、固定模型，让学习者自由装配八个 Agent 零件，运行并观察完成度、结论、工具调用、模型回合、模拟耗时与逐事件 Loop。

## 2. 目标

- 在同一固定任务中提供可拆卸、可装入、可重新运行的 Agent 装配体验。
- 让学习者通过单变量对照理解八个零件各自补上的失败模式。
- 同时展示“能不能做”“有没有边界”“有没有证据”“是否通过验收”，不合并成单一总分。
- 用逐事件重放展示组件在 Loop 中的参与位置和调用方式。
- 自动比较最近两次运行，并保留最近六次装配供再次载入。
- 在不调用模型、不执行工具的前提下，提供稳定、无随机扰动的学习沙盒。
- 保留现有从零建造课程和真实 Trace 视图。

## 3. 用户故事或实验场景

- 作为 Agent 初学者，我希望先运行“只有模型”，亲眼看到它在第一步就没有动作能力，而不是只读一句结论。
- 作为学习者，我希望只装入 `read_file` 后再次运行，看见动作发生了但 Observation 无法回到下一轮。
- 作为产品学习者，我希望把“能干活”和“完整可信”并排比较，理解新增治理零件改变了什么、成本是多少。
- 作为实验者，我希望点击任意零件查看它的方法、位置和介入时机，并在事件重放时看到它何时高亮。
- 作为复盘者，我希望载入之前的装配，继续拆掉一个零件再运行，形成自己的对照实验历史。
- 给定页面没有 `dashboard/data.json`，乐高实验仍能完整使用。
- 给定我使用键盘或手机，我仍能通过点按完成全部装配操作。

## 4. 范围

- 新增独立 `06 乐高实验` 视图，不依赖真实 Eval 数据。
- 提供八个可选零件，按三个平面组织：
  - 动作积木：`read_file`、`write_file`、`run_python`；
  - 回路积木：`loop`、`registry`；
  - 系统积木：`guardrail`、`trace`、`eval`。
- 固定一个任务、一个脚本化模型和一个确定性 fixture。
- 支持点按装入/拆下；支持 HTML5 拖拽作为等价桌面交互。
- 提供四个快速装配起点：只有模型、只加读取、能干活、完整可信。
- 运行时逐事件重放，并高亮本轮参与组件。
- 展示完成度、任务状态、工具调用、模型回合、模拟耗时、安全状态、证据状态和逐项交付检查。
- 自动比较最近两次运行，并保留最近六次运行的装配与结果。
- 更新导航、README、ROADMAP、规格索引、CLI 版本和实现记录。

## 5. 非目标

- 不调用任何模型 API，不执行文件、Shell 或 Python。
- 不实现 Live Eval、真实任务运行、在线调参或自定义任务。
- 不允许更换模型 Provider、Prompt、fixture 或温度。
- 不证明某个组件在所有任务、模型或生产环境中都有收益。
- 不提供单一“Agent 总分”，也不把模拟耗时当作实际性能基准。
- 不把教学重放伪装成真实 Trace。
- 不实现 Skill、MCP、RAG、Memory、Subagent 或多 Agent。
- 不持久化历史；刷新页面后实验记录清空。

## 9. 指标

固定任务为“把 `config.py` 的 `VERSION` 从 `1.2.0` 改为 `1.3.0`，并运行测试”。教学结果如下：

| 装配 | 完成 | 状态 | 工具调用 | 模型回合 | 模拟耗时 |
|---|---:|---|---:|---:|---:|
| 只有模型 | 0/3 | `BLOCKED` | 0 | 1 | 0.72s |
| 只加读取 | 1/3 | `INCOMPLETE` | 1 | 1 | 0.90s |
| 能干活 | 3/3 | `UNVERIFIED` | 3 | 4 | 3.42s |
| 完整可信 | 3/3 | `PASS` | 3 | 4 | 3.88s |

模拟耗时公式：

```text
模型回合 × 720ms
+ 工具调用 × 180ms
+ Guardrail × 45ms/工具
+ Registry × 25ms/工具
+ Trace 20ms + 事件数 × 8ms
+ Eval 90ms
```

该公式只用于比较装配带来的教学复杂度，不是网络延迟、模型延迟、工具执行时间或性能基准。

## 10. 安全与边界

- 乐高实验是静态前端教学模拟，不包含 API Key、网络请求、模型调用、文件写入或子进程执行。
- 页面中的工具值、Observation、测试通过和 Trace 都是确定性教学数据。
- 装配结果只能说明当前教学模型内部的因果规则，不能外推为某个真实 Agent 在今天、某个模型上会成功。
- `Guardrail PASS` 仅表示本次脚本动作经过教学边界检查，不表示系统具备 OS 级或容器级 Sandbox。
- `Trace ON` 仅表示教学系统有可观察事件，不等于真实生产环境的完整审计。
- `Eval PASS` 仅表示固定教学契约的三项检查都有证据，不等于通用能力认证。
- `dashboard/data.json` 仍是本地未脱敏数据；本实验不读取或提交该文件。

## 11. 风险与未决问题

- 风险：学习者把确定性模拟误认为真实运行。缓解：入口、运行面板和结果区持续标注，不展示真实密钥或网络活动。
- 风险：把“更多零件”误读为“更先进”。缓解：明确 Registry、Guardrail、Trace 不提高固定任务的模型解题能力，只分别改善契约、安全与可审计性。
- 风险：模拟耗时被当成性能数据。缓解：公开公式，标注“教学估算 / 非网络实测”，在 A/B 中只作成本变化提示。
- 风险：拖拽在自动化环境中的合成事件不稳定。缓解：点按与拖拽等价；点击路径作为完整可用与验收路径，不夸大自动化拖拽验收。
- 待决：真正可执行的自定义装配实验需要独立 Sandbox、资源限制、审批和进程清理，不属于本期。
- 待决：浏览器刷新后的实验历史是否持久化，需要先设计版本、脱敏与清理策略。
