# ADR-004：Agent Anatomy 采用本地只读投影

- 状态：Accepted
- 日期：2026-10-28
- 关联：`m1.3-agent-anatomy`

## 背景

已有 Eval 和 Trace 能证明 Agent 行为，但 JSON 不利于学习模块边界、Loop 顺序和配置差异。交互执行网页会同时引入密钥、进程、文件内容、审批和公开部署风险，超出当前要验证的问题。

## 决策

使用 Python 标准库导出真实 registry 与 Eval 报告，使用原生静态网页展示。生成数据仅保存在本机并被 Git 忽略。页面不提供模型调用、工具执行、任意 workspace 或自由流程编排。

新工具事件增加 `call_id`；旧报告由导出器进行确定性的最佳努力关联并标明推断。字符截断只控制载荷，不被描述为脱敏。

## 备选方案

1. 直接引入交互式 Web 后端：能调参运行，但扩大安全与状态管理范围，拒绝。
2. React/图表框架：生态丰富，但当前三视图不需要构建链和新增依赖，拒绝。
3. 在浏览器重复实现 Eval 解析：减少导出命令，但会形成两套数据契约，拒绝。
4. 提交脱敏演示数据：便于公开预览，但容易把演示与真实运行混淆，本里程碑拒绝。

## 后果

优点是无新增运行依赖、数据来自真实运行、可随时回滚。代价是每次更新报告后需要重新导出；公开分享前必须另做脱敏导出；旧报告无法恢复未记录的完整 prompt 或代码 revision。

后续若增加调参运行，必须新建规格，单独设计固定任务、临时目录、审批、取消、密钥和进程边界。
