# ADR-003：采用可回退的滚动历史压缩

状态：Accepted

日期：2026-10-28

## 背景

M1.1 证明工具 observation 会一直留在消息历史中。长文件逐页读取、多文件取证和重复压缩会让后续每次模型请求都携带旧内容，即使这些内容对当前决策已经没有同等价值。

候选方案包括：

1. 不压缩，只依赖单条 observation 截断；
2. 删除旧消息，只保留最近窗口；
3. 把旧消息交给模型生成摘要；
4. 使用确定性规则提取证据，再可选地用模型改写摘要。

单纯截断只能控制单条结果，无法控制历史累积；直接删除可能丢失文件名、行号、错误和未完成事项；完全依赖模型摘要成本更高，也可能改写关键值或编造未执行的事实。因此需要同时验证“压缩是否有效”和“压缩是否保真”。

## 决策

采用滚动历史压缩，默认配置为关闭：

- 提供 `off`、`extractive`、`model` 三种策略；
- 仅依据 Provider 返回的真实 `prompt_tokens` 触发，不按字符数伪造 Token；
- 保留原始 system、最新 user、最近消息窗口和最新用户任务；
- 压缩边界不得拆散 assistant `tool_calls` 与对应 tool message；
- `extractive` 确定性提取工具名、来源路径、行号、错误、TODO/FIXME、分页元数据和任务关键标识，并去重；
- `model` 只负责改写已有证据，不提供工具；空响应、异常、工具调用、超限或缺失必需证据时回退到 `extractive`；
- 如果候选摘要不比原上下文更小，则不修改消息历史；
- 压缩只替换下一次模型请求使用的历史，原始 Trace 保留压缩前的工具调用和 observation；
- `off` 保持 M1.1 行为，作为对照组和回滚开关。

## 理由

- 真实 usage 才代表 Provider 看到的上下文占用，字符估计适合观测但不适合作为精确触发条件；
- 证据优先的确定性摘要可复现、成本低，也是模型摘要失败时的安全底座；
- 默认关闭避免在尚未验证收益和失真之前改变所有任务的运行条件；
- 保留原始 Trace 让压缩后的行为仍可回溯到未经改写的证据；
- 三种策略要求同一任务集、同一模型和同一实验预算对照，避免只展示成功案例。

## 后果

- 压缩会改变消息序列，必须持续维护协议边界测试；
- 摘要长度有上限，极端情况下可能无法保存全部证据，或因为不产生净收益而放弃压缩；
- `extractive` 只能保留规则可识别的信息，不能保证语义完整性；
- `model` 会产生额外 Token、延迟和外部服务失败点；
- 自动事实检查只能验证关键字符串存在，不能证明摘要没有断章取义；
- 当前验证只覆盖固定任务和少量模型运行，不能外推为跨模型稳定结论；
- 真正的隔离、持久记忆和语义检索仍不属于本阶段范围。

## 未采用的方案

- **只删除最旧消息**：实现简单，但容易遗漏隐藏在当前任务中的旧证据。
- **每轮都让模型总结**：成本高且引入不必要的非确定性，也没有证据表明优于确定性提取。
- **仅使用字符阈值触发**：与 Provider 实际计费和上下文窗口脱节，无法复用真实 usage。
- **压缩后覆盖 Trace**：会失去复盘和审计能力，无法判断错误来自原始 observation 还是摘要。
